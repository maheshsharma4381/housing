# Phase 7 — The installable app (PWA) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Sahvaas installs on a phone like an app. That means:
- proper icons on Android and the iPhone Home Screen;
- the service worker registered for every visitor, not only when push is enabled;
- an offline page in place of the browser's error;
- an "Install app" button inside the app.

**Spec:** `docs/superpowers/specs/2026-10-31-sahvaas-simplify-design.md`:
- section 2, non-goals: "Native mobile apps. The app stays a web app / installable PWA";
- 8.1: iPhone "Add to Home Screen";
- 8.3: "iPhone Home Screen needs PNG icons".

## Global Constraints
- No native app (spec non-goal). The PWA is "the mobile app".
- Push stays payload-free (3A); the service worker keeps that behaviour.
- App UI in English.

## Review Focus
1. Android's installability criteria: manifest icons at 192 and 512 PNG, plus a maskable icon.
2. The iPhone uses `apple-touch-icon` (180 PNG), not SVG.
3. The service worker never caches API calls or signed-in pages. Money data must never be served stale. Only the offline page is cached.
4. Registering the service worker for everyone does not break push (same `/sw.js`, same scope).

- [ ] `src/lib/sw-policy.ts` holds `swShouldHandle(request)`, unit-tested: only navigations; never /api; never cross-origin.
