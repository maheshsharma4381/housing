# Phase 11A (flat requests + NOC letters) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Owners (and tenants, for allowed types) request NOC letters with documents; the committee approves, asks for changes or rejects; an approved NOC becomes a numbered letter with the flat's dues line, kept in a NOC register.

**Architecture:** A generic request engine (`flat_requests`, `request_documents`, `request_events`) with RLS-hidden tables and `SECURITY DEFINER` RPCs; NOC kinds are configured per society in `noc_types` (seeded with defaults); approval of a NOC request renders the template server-side into `noc_letters` with the next `NOC/{FY}/{nnn}` number. Files sit in a private `request-files` bucket. The letter is a printable page (browser "Save as PDF"), like the flat statement.

**Tech Stack:** Next.js 15, React 19, Tailwind v4, Supabase Postgres + Storage, PGlite DB tests, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-24-flat-changes-design.md` (sections 5.1, 5.2)

**Choices the spec left open, made here:**
- Requests start as `submitted` (no draft); documents can be added while `submitted` or `changes_asked`. Statuses in 11A: `submitted`, `changes_asked`, `approved`, `rejected`, `withdrawn` (`done` comes with later kinds).
- The NOC checklist lives on each NOC type (`noc_types.checklist`); a request snapshots it.
- The letter is stored as its rendered text (`noc_letters.body`) plus header fields; "PDF" is the printable page. No file is generated on the server.
- The share certificate number is a new column `units.share_certificate_no`, set by managing roles (on the request screen and by RPC).
- NOC fees are not in 11A (they need 11C's one-off flat charge).

## Global Constraints

- Migration `src/db/migrations/040_flat_requests.sql` (Gate Lite moves to 041); `bun run db:bundle`. Never edit 001–039.
- New functions `SECURITY DEFINER SET search_path = public`; helpers revoked from `PUBLIC, anon, authenticated`; RPCs granted to `authenticated`.
- "Owner of a flat" = an active membership on the flat with role `resident_owner` or a committee role (as Phase 10's polls). "Managing roles" = `is_society_admin`; "committee viewer" = `is_committee_viewer`.
- Dues line uses `party_entries(society)` for the flat up to the issue date (same entries as My account): sum > 0 → `Dues of ₹{amount} are outstanding as on {date}.`; otherwise `There are no dues outstanding as on {date}.` Amount formatted Indian style with 2 decimals (`inr_text` is not used; `to_char` with Indian grouping via a helper).
- Number: `NOC/{FY}/{nnn}`, FY like `2026-27` from the issue date in Asia/Kolkata (April–March), `nnn` zero-padded to 3, per society per FY, never reused.
- Pending warning: NOC requests 25+ days after submission show amber with `A NOC must be decided within one month of the application.`
- Default letter texts carry no legal claims beyond the placeholders; the templates screen shows `Check this wording with your society's legal adviser.`
- English UI only; all plans; no ad slots.
- DB tests one file at a time: `TZ=UTC node --test tests/db/<file>.test.mjs`. Unit: `node --test tests/unit/<file>.test.ts`.

## Review Focus

1. A tenant asks for a sale or loan NOC: refused; a tenant can ask only for types marked "tenants can ask" (Task 2).
2. Two approvals in the same financial year get 001 and 002; the first approval after 1 April starts again at 001 under the new FY (Task 3).
3. The flat has an advance (negative balance): the letter says no dues, never "Dues of ₹-500" (Task 3).
4. A required document is missing: Approve is refused with the item's name (Task 3).
5. Another flat's owner, a tenant of another flat, or another society cannot read the request, its documents or its letter (Tasks 2, 4).

### Task 2: Requests, documents and the history

**Files:** Modify `040_flat_requests.sql` (section 2); Test `tests/db/flat-requests.test.mjs`

**Produces:**
- `flat_requests(id uuid pk, society_id, unit_id, kind varchar(16) check in ('noc','tenancy','shifting','transfer'), noc_type_id uuid null, applicant_id uuid, status varchar(16) check in ('submitted','changes_asked','approved','rejected','withdrawn','done'), details jsonb default '{}', checklist jsonb, committee_note text, submitted_at timestamptz default now(), decided_at timestamptz, decided_by uuid, created_at)`; index `(society_id, status, submitted_at)`.
- `request_documents(id uuid pk, request_id fk cascade, item_key varchar(16), path text, file_name varchar(160), uploaded_by uuid, uploaded_at timestamptz)`.
- `request_events(id uuid pk, request_id fk cascade, actor uuid, action varchar(24), note text, at timestamptz default now())` — actions `submitted, document_added, document_removed, resubmitted, changes_asked, approved, rejected, withdrawn`.
- helper `can_see_request(p_request_id uuid) RETURNS boolean`: committee viewer of its society, or the applicant, or an owner of its flat (owner rule above). Granted to `authenticated` (storage policies use it).
- RLS SELECT on all three tables via `can_see_request`; no write policies.
- `create_noc_request(p_unit_id uuid, p_noc_type_id uuid, p_purpose text, p_addressee text) RETURNS uuid`: caller is an owner of the flat, or a tenant of it when the type has `tenant_can_ask`, or a managing role; type active and of the same society. Errors: `Only an owner of this flat can ask for this NOC`, `This NOC is not available`, `Write the purpose (3 to 300 characters)`, addressee ≤ 160 (`The addressee can be up to 160 characters`). Snapshots the checklist; event `submitted`; notifies managing roles: kind `request`, title `NOC request: {type} for flat {label}`, link `requests`.
- `add_request_document(p_request_id uuid, p_item_key text, p_path text, p_file_name text) RETURNS uuid`: caller can edit (applicant, an owner of the flat, or a managing role); status `submitted` or `changes_asked`; key in the snapshot; path matches `^{society}/{request}/[^/]+$`. Errors: `This request can no longer be changed`, `Choose a document from the list`, `That file does not belong to this request`, `Only the applicant or the committee can do this`.
- `remove_request_document(p_document_id uuid) RETURNS void` (same rights and statuses).
- `withdraw_request(p_request_id uuid) RETURNS void` (applicant or owner; status `submitted`/`changes_asked`).
- `resubmit_request(p_request_id uuid, p_note text) RETURNS void` (applicant or owner; from `changes_asked` → `submitted`; notifies managing roles).
- Bucket `request-files` (private, 10 MB, `application/pdf, image/jpeg, image/png, image/webp`, ON CONFLICT DO UPDATE). Storage policies: INSERT when the path's request (2nd folder) is in the path's society (1st folder) and `can_edit_request`; SELECT when `can_see_request`.

### Task 3: Decisions and the NOC letter

**Files:** Modify `040_flat_requests.sql` (section 3); Test `tests/db/flat-requests.test.mjs`

**Produces:**
- `noc_letters(id uuid pk, society_id, request_id uuid unique fk, number varchar(24), fy varchar(7), seq int, issued_on date, type_name text, title text, body text, signatory text, issued_to text, flat_label text, dues_amount numeric, created_by uuid, created_at)`; unique `(society_id, fy, seq)`; RLS SELECT via `can_see_request(request_id)`.
- helpers (revoked): `fy_label(p_date date) RETURNS text` (`2026-27`); `flat_label(p_unit_id uuid) RETURNS text` (`A-101` when the society has more than one wing with that number, else the number — same rule as `flatLabels`); `flat_dues_on(p_unit_id uuid, p_on date) RETURNS numeric` (sum of `party_entries` for the flat up to the date); `indian_money(p_amount numeric) RETURNS text` (`1,23,456.50`); `render_noc(p_request_id uuid, p_on date) RETURNS jsonb` (`{title, body, dues_amount}` with every placeholder replaced; empty values → `—` except `{share_certificate_no}` → `not recorded`).
- `decide_request(p_request_id uuid, p_decision text, p_note text) RETURNS jsonb` (managing roles): `approve` (status `submitted` only; every required checklist item has a document, else `Add "{label}" before approving`), `changes` (note 3–500 required → `Write what needs to change`), `reject` (note required → `Write the reason`). Approve of a NOC request inserts the letter (number from `max(seq)+1` for the society and FY, inside the transaction with a row lock on the society's requests) and returns `{letter_id, number}`. Notifies the applicant: `NOC approved: {type}` / `Changes needed: {type}` / `NOC request declined: {type}`, link `requests`. Events recorded.
- `noc_preview(p_request_id uuid) RETURNS jsonb` (committee viewers): the rendered text for today, so the committee sees it before approving.
